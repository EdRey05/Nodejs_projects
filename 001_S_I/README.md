# Personal Savings & Investing Tracker

Version **1.0.0**. A Windows portable app for tracking savings, managed investing and self-directed portfolios from a local Excel workbook. It is not connected to any financial institution.

[Watch the walkthrough](https://github.com/EdRey05/Nodejs_projects/blob/main/Images_GIFs_Videos/001_S_I.mp4). The demo uses only fictional data: native workbook selection, a savings contribution and projection, then the managed and self-directed dashboards. Only file-browser navigation is accelerated; dashboard actions and pauses keep their original pace.

The portable package includes one example: `examples/Synthetic_Portfolio.xlsx`. Copy it before experimenting.

Extract the portable ZIP and double-click Start.cmd. In **Manage & Import**, choose **Open workbook** and select your .xlsx file with the Windows picker. Accounts and transaction edits save back to that same file automatically. The status bar shows its path and Saving/Saved or a recoverable error. On the next launch, the app reads that file again if it is valid. Wait for Saved before using Stop.cmd to stop the background service.

Use **Export** to download a separate copy. **Import a temporary copy** retains the old .xlsx/.xls upload workflow without linking a writable file; edits to a temporary copy need Export. The browser warns before closing a page with unsaved edits. If the remembered file is moved, missing or invalid, choose it again; it is never replaced by blank data. If Excel locks the file, close it and retry saving. If another program/page changes it, export your unsaved edits or explicitly reload the file before continuing.

The remembered path is stored locally in `%LOCALAPPDATA%\SavingsInvestingTracker\settings.json`, independently of browser and launch port. Before writing, the app retains the first original and previous version under that folder's `backups/` (file names use a hash of the full workbook path). Saving uses a temporary file and replacement, updates the four app data sheets and retains other worksheet values where supported by the Excel library. Complex Excel formatting/features are not a preservation guarantee; the original backup remains available. No workbook is uploaded to a cloud service.

Workbook sheets: Accounts (required), S_Transactions, I_M_Transactions and I_SD_Transactions. Accounts use id, name, bank, type (savings/investment), optional interestRate and subtype (managed/self-directed). Transactions use id, accountId, type, amount and ISO date (or native Excel dates). Trades require assetCode and positive shares; assetName and assetCategory describe the holding. Keep account IDs unique and transaction accountId values linked to them. [Synthetic_Portfolio.xlsx](../demo-data/001/Synthetic_Portfolio.xlsx) provides 451 fictional transactions across three accounts; [sample details and expected balances](../demo-data/README.md).

Self-directed balances use cash plus remaining holdings at average cost. Deposits add cash, purchases move cash into holdings, sales remove average cost and return proceeds to cash, and income adds cash. Realized sale gains affect the balance; there are no live prices or unrealized gains. Cash appears below the main balance and is calculated from activity, without a separate manual balance entry. Cash movements contains only contributions from your pocket and withdrawals to your pocket; record dividends, interest and other payouts under Trades & income. Dates belong to those activity records so historical charts remain accurate. Allocation excludes cash and uses remaining cost after sales; the two charts show holdings and recorded asset income with one shared legend. Hover a slice for its category, amount and percentage. Income charts show payouts rather than total investment return.

Older workbooks without categories inherit category metadata from other rows for the same account/ticker, then infer it from recognizable names/tickers. Supported categories are Stock ETF, Individual Stock, REIT and REIT ETF; add an explicit assetCategory in the workbook to correct an inference. Unrecognized ticker-only assets stay Uncategorized. If an old trade history has no deposits, the dashboard explicitly reports inferred purchase funding. Partial deposit histories cannot be reconstructed automatically; supply the missing cash movements. Export saves normalized metadata, while inferred funding remains a displayed assumption rather than an invented transaction in your workbook.

The self-directed Account Growth card switches between history and an editable projection, initially 7% annual growth, $500 monthly contributions and ten years. Like the other dashboards, it compounds the annual rate divided by twelve each month and adds contributions at month end. Hover for starting balance, cumulative contributions, estimated growth and projected balance. This scenario starts from the recorded cash-plus-cost balance; it does not retrieve current market prices. The six asset charts include cumulative realized trade gains (sale proceeds less average cost of shares sold), separate from income and unsold holdings.

All chart month labels use four-digit calendar years, such as Oct 2026. Charts and projections reflect the app's simplified calculations, not brokerage valuation or financial advice. No AI, cloud account or API key is required. System fonts work offline.

Source development: npm ci, npm run typecheck, npm test, npm run build, npm start. Portable builds: [shared instructions](../build-tools/README.md). [MIT license](../LICENSE).
